框架层：教程是怎么组装起来的
关键理解点
      整份教程的"骨架"只有 20 多行真代码，位于 
script.rpy
：一个 
Section
 类 + 一个 
Tutorial
 类，
      每个 
Tutorial("label", "标题")
 会把自己追加进全局列表 
tutorials
；
screen tutorials
 遍历这个列表生成目录；
label tutorials
 用 
call expression tutorial.label
 跳进章节，回来后再跳回目录 —— 于是形成一个"目录 ↔ 章节"的循环。
      这条链路上还有两个容易被忽略的机制：
示例内嵌
章节里写的每一段教学代码，都用 
#begin 名字
 / 
#end 名字
 包起来；
01example.rpy
 在 
init python
 阶段
扫描全部 .rpy 源文件
，用正则把片段抠出来存进字典，
        再交给 
example
 屏做语法高亮 + 复制按钮。也就是说：
屏幕上显示的示例代码，就是源文件里真实运行的那段代码
，永不过期。
运行时换装
01director_support.rpy
 用 
python early
 在启动最早期把 
tutorial_director.rpym
 复制成 
tutorial_director.rpy
，
        从而"按需"把导演演示挂进游戏；复制失败（只读介质）时降级为只读模式。这就是目录里同时存在 
.rpy
 与 
.rpym
 两份 75 行文件的原因。
      这也解释了 
log.txt
 里的一条记录：
Init at game/01example.rpy:571 took 6434 ms
 ——
      那次 6.4 秒的启动开销，正是"扫描 + 抠取 + 高亮全部示例"这一步，是整个启动流程里最重的操作。

09
结论与结构观察
10 条，按重要性排列
①
这是"可运行的教学工程"，不是普通游戏
project.json
 用 
{"type":"hidden","tutorial":true}
 标记自己：启动器不显示它，但引擎知道它是官方教程。
          602 个文件中真正的教学内容只有 24 个英文 
.rpy
（9,512 行，另加 1 个 75 行的 
.rpym
 副本），其余是翻译、素材和缓存。
②
三层结构非常清晰，扩展成本极低
          新增一个教程章节只需要两步：写一个 
label
，然后在 
script.rpy
 里加一行 
Tutorial("label", "标题")
。
          目录屏、进度记忆、章节前后的小动作（
move_before
/
move_after
）全部由框架自动处理。
          这是这份工程最值得借鉴的设计。
③
目录里唯一的"重复文件"是刻意的
tutorial_director.rpy
 与 
tutorial_director.rpym
 内容相同（各 75 行），
          原因是 
01director_support.rpy
 在 
python early
 阶段把 
.rpym
 复制成 
.rpy
 来"热插拔"导演演示。
          这也解释了另一个数据：
源码 238 个，编译产物只有 237 个
 —— 缺的那一个正是 
tutorial_director.rpym
（它的编译走的是 .rpy 那条路）。
④
体积完全被素材支配，代码只占 1/4
          图片 + 音频 + 视频 = 25.3 MB（
77.2%
），其中 3 张 concert 图 12.4 MB、1 首 BGM 3.7 MB。
          工程"重"不在代码，而在示例素材 —— 这与"教学要肉眼可见的效果"的目标一致，但如果要压缩分发体积，
先处理这 4 个文件就能省掉近一半
。
⑤
翻译层是"镜像复制"，不是手写的第 11 份代码
          10 种语言 × 约 21 个同名文件，每个语言行数都落在 7,065~7,445（均值 ±3.5% 内），
          文件名与英文源一一对应，且 
.rpy
/
.rpyc
 严格成对。
          这说明它们是同一次 
renpy.sh translate
 批量生成的，后续人工只填了译文。
⑥
Italian 包存在成对的重复 translate 块
italian/indepth_style.rpy
 中约 120 个 translate 块全部出现两次，
tutorial_quickstart.rpy
 块数 259（其他语言 143）。
          后果：该语言多出约 2,400 行重复条目；功能上后者覆盖前者，不会报错，但会掩盖真正的翻译遗漏，也让校对成本翻倍。
⑦
tl/None 是引擎回退层，别当语言数
          目录里那个 747 行的 
common.rpym
 全是 
old X / new X
 的恒等映射，
          用途是"任何语言缺条目时显示原文"。统计语言数时应记 
10 种
，而不是 11 种。
⑧
启动耗时几乎全在一处：示例片段扫描
log.txt
 显示 init 共 6.8 秒，其中 
01example.rpy:571
 的"扫描全部 .rpy → 正则提取 
#begin/#end
 → 高亮"占 6.4 秒。
          换来的是"示例代码永不过期"这一强保证。如果要在低端设备/Web 上优化首启，这里是唯一值得动的地方（例如离线预生成 
.rpyb
）。
⑨
目录里有 7 个"不该入库"的运行时文件
log.txt
、
cache/screens.rpyb
、
cache/shaders.txt
、
saves/*
（3 个）、
          以及被复制生成的 
tutorial_director.rpy
 —— 时间戳都是 2026-09-22（运行日），其余 595 个文件是 2026-05-16（打包日）。
          版本管理或二次分发时应把这一组排除。
⑩
它同时还是 Web 版与自动化测试的样例
progressive_download.txt
 是 RenPyWeb 渐进下载配置，
testcases.rpy
 是引擎自测套件（含按语言跑的用例）。
          也就是说这份工程的职责有三重：
教学示例 + 引擎回归测试 + Web 构建示范
。
          阅读它时，遇到看不懂的代码先判断它属于哪一重身份。
如果要复用它，建议的进入顺序
1
先读 220 行的 script.rpy
：30 行类定义 + 1 个目录屏 + 3 个标签，教程的全部调度逻辑都在这里。
2

 + 
01example.rpy
 的 
init python hide
 段：理解"源码即示例"的渲染管线，这是全工程最巧的一处。
3
挑一个章节当模板
：想看最小案例读 
indepth_character.rpy
（163 行）；想看完整结构读 
tutorial_quickstart.rpy
（621 行 / 9 章）。
4
做 UI 就抄 screens.rpy + gui.rpy
：这是新建工程的标配，与教程内容无关，可直接搬到自己项目。
5
要改语言才看 tl/
：文件名与源一一对应，改完直接 
renpy.sh
 重编译即可。
统计口径：文件数含隐藏文件；行数为 
.rpy
/
.rpym
 的物理行（含注释与空行）；体积按 1024 进制。
生成方式：PowerShell 递归枚举 + 分组统计，二进制文件（.rpyc/.rpyb/.save）不计行数。

01
你打开的是什么
先花两分钟搞清楚定位
    这是 Ren'Py 安装目录里自带的 
Tutorial
 工程。运行它，你会看到角色 Eileen 站在白宫前跟你打招呼，
    问你想学什么；点开任意一项，它就
当场演示
一个功能（比如让图片滑进来、让文字闪烁、放一段视频），
    同时把实现这段效果的代码显示在屏幕上。
    所以它的身份有点特殊：
它既是一个游戏，也是一本可以点的说明书
。
    你要学 Ren'Py，最有效的用法不是「读它的源码」，而是「一边玩一边看它当场展示的代码」。
一个诚实的提醒
script.rpy
 开头，作者自己写了一句大实话（大意）：
      「
这其实是 Ren'Py 编程风格的一个不太好的例子
 —— 我们在教程里展示的例子本身是好的，但为了让它们方便演示，
      用了很多非常规的高层写法。如果你想看
好的
 Ren'Py 代码长什么样，去看 
The Question
。」
      结论：
把它当「功能字典」用
（想做某效果时来查），不要把它当「我的第一个项目的模板」照抄。
      真正的模板请用启动器新建工程，或者看 The Question。

03
名词小抄：看到这些词不用慌
12 个词，够你读完这个工程
    新手最容易被两样东西劝退：一堆文件后缀，和文档里的术语。下面每个词只给一句话，外加一个生活化的类比。
.rpy
你写的剧本
Ren'Py 的源代码文件。台词、图片、菜单、逻辑都写在里面，用文本编辑器就能改。
Word 文档
.rpyc
自动生成的
引擎把 .rpy 编译后的版本，让游戏启动更快。
永远不要手改
，改 .rpy 后它会自动更新。
Word 导出的 PDF
.rpyb
在 cache 里
引擎的字节码缓存（记录 Python 部分和界面分析结果）。可以安全删除。
浏览器的网页缓存
.rpym
可插拔模块
一种「需要时才装进来」的脚本。这个工程里只有一个（导演演示），用来演示运行时热插拔。
U 盘里的绿色软件
label
章节书签
剧情可以跳转的锚点，写法是 
label start:
。跳转用 
jump
 或 
call
。
书里的「第 3 章」页码
screen
界面
一块可交互的界面：标题画面、对话框、设置页、技能栏都算。这个工程里有 38 个。
PPT 的一页版式
init
开场前的准备
游戏真正开始前执行的代码块，用来定义角色、图片、变量、样式。启动时按顺序跑一遍。
演出前的布景
define / default
定义与变量
define
 定义不变的东西（角色、图）；
default
 定义会变的数值（好感度、金币）。
演员表 vs 计分板
displayable
能显示的东西
屏幕上任何可见元素：图片、文字、按钮、进度条。界面就是由 displayable 拼起来的。
乐高积木
ATL / transform
动画与站位
控制「图片怎么动、动多久、停在哪」。让立绘从左边滑到中间，就是几行 ATL。
舞台调度
translate / tl
翻译
把界面文字和台词换成别的语言。一个语言一个文件夹，和源文件同名同构。
电影的配音轨
persistent
持久数据
跨存档保留的记忆：已读文本、解锁的 CG、上次选的语言。删了等于清空成就。
游戏卡带里的电池存档
04
这个游戏是怎么跑起来的
看懂这 6 步，你就看懂了任何 Ren'Py 游戏
    Ren'Py 的执行顺序是固定的。把下面这条链子记住，以后遇到任何工程都能对上号 ——
    也能解释「为什么我改了文件却没生效」「为什么启动要 6 秒」这类问题。
1
引擎读配置
先读 
options.rpy
（游戏名、分辨率、存档位置）和 
gui.rpy
（颜色、字体），再读 
screens.rpy
 里定义的界面。
2
跑 init 代码
所有 
init
 块按顺序执行 —— 定义角色 Eileen、加载图片、注册章节。
这一步最慢
：本工程的启动日志里，总共 6.8 秒有 6.4 秒花在这里。
3
进入 label start
游戏永远从 
label start
 开始。这里它放了背景和音乐，Eileen 出来说第一句欢迎词。
4
显示教程目录
screen tutorials
 把注册好的 26 个章节画成一个可滚动的列表，等你点。
5
跳进你点的那一章
一行 
call expression
 跳到对应 label，比如「写对话」跳进 
tutorial_dialogue
。章节演完自动回来。
6
回到目录，循环
这就是为什么你能一直点下去。
整个循环只有 20 来行代码
，就在 
script.rpy
 里，非常好读。
延伸一步：加章节有多简单
      因为目录是自动生成的，你要加一个教学章节只需要两步：
①
 写一个 
label 我的章节:
；
②
 在 
script.rpy
 里加一行 
Tutorial("我的章节", "标题")
。
      菜单会自动多出一条，你不需要碰界面代码。这个「注册 + 自动生成」的思路，可以直接搬到你自己的游戏里做章节选择。

07
新手最常问的 8 个问题
点开看答案
为什么每个 .rpy 旁边都有一个 .rpyc？能删吗？
那是引擎编译后的版本，作用是
让游戏启动更快
（不用每次重新解析你的剧本）。它和 .rpy 是一一对应的：本工程 236 个 .rpy，就有 236 个 .rpyc。
不要删，也不要手改。
 你改了 .rpy 保存后，下次运行引擎会自动重新生成对应的 .rpyc。手改 .rpyc 没有任何意义，因为它会被覆盖。
唯一需要知道的是：
分发游戏时两者都要带上
，只给 .rpy 会让启动变慢。
tl/ 里那 200 多个文件是什么？我不管它会出错吗？
是
翻译
。10 种翻译：法语、俄语、西班牙语、意大利语、葡萄牙语、乌克兰语、韩语、日语、简体中文，再加一个演示用的「猪拉丁」（Pig Latin，故意造出来的玩笑语言）。每个语言一套和英文同名的文件。
不会出错。
游戏只会加载当前选中的那一种语言
，其余的启动时会直接跳过 —— 启动日志里那句「212 script files skipped」说的就是这件事。
这堆文件占了全部脚本行数的 88%，所以你看到的「84,583 行代码」其实只有 9,512 行是真正的英文教学内容。
它才 26 个章节，为什么要占 32 MB？我的游戏也会这样吗？
体积几乎全是素材：
图片 20.6 MB + 音频视频 4.8 MB = 77%
。其中光是三张演出现场背景图就 12.4 MB，一首背景音乐 3.7 MB。
代码本身只有 3.7 MB（其中还包括 74,324 行翻译）。
你的游戏不会自动这么胖 —— 它这么胖是因为要塞进大量高质量的演示素材。
文字游戏的实际体积主要由图片决定
，一张 1920×1080 的 PNG 通常 1~2 MB，你可以据此估算自己的项目。
为什么启动要 6 秒？是我的电脑太慢吗？
不是。这个工程做了一件很特别的事：它启动时
扫描自己所有的 .rpy 源文件
，把用 
#begin xxx
 和 
#end xxx
 包起来的代码片段全部抠出来，用于在屏幕上做代码高亮显示。
日志里写得很清楚：init 总共 6.8 秒，其中 
game/01example.rpy:571
 这一处就花了 
6.4 秒
。这是「教程」独有的开销，普通游戏不会这样。
cache/ 和 saves/ 能删吗？删了会怎样？
cache/
：随便删。里面是引擎的临时缓存（字节码、界面分析、着色器列表）。下次启动会自动重建，代价只是第一次启动慢几秒。
saves/
：删了就等于
清空存档
。注意里面还有一个叫 
persistent
 的文件，它记着「哪些文本已读、解锁了什么、上次选的语言」—— 删掉它，已读记录和成就会一起消失。
打包发布时，这两个目录都应该排除在外。
为什么有两个 tutorial_director（.rpy 和 .rpym）？是重复了吗？
不是失误，是刻意设计。这个工程想演示「按需加载一个脚本模块」：平时只有 
.rpym
，当你进入「交互式导演」那一章时，
01director_support.rpy
 会在启动最早期把它
复制成 .rpy
，模块才真正生效。
你在游戏里看到的「导演」功能就是这么被加载进来的。对你的启示是：Ren'Py 允许在运行时增删脚本，这在做「试玩版 / 付费解锁内容」时很有用。
我改了 .rpy，为什么游戏里没变化？
九成是这三种情况：
1. 游戏还开着。
 正在运行的游戏不会重新读文件。
先完全关掉游戏再启动
（Ren'Py 没有热重载）。
2. 你改的是 .rpyc。
 那是编译产物，改了会被覆盖。要改 .rpy。
3. 改的代码没被执行到。
 比如你改了一个 label，但根本没跳到那里；或者改的界面被别的样式覆盖了。用「启动器 → 强制重新编译」或删掉 .rpyc 再运行，能排除缓存问题。
我能直接把这个工程改成自己的游戏吗？
技术上可以（复制整个文件夹，改 
project.json
 去掉 hidden，删掉 tutorial_*.rpy 那堆章节），
但不推荐
。
原因：这个工程为了让「演示」方便，用了很多非常规写法（作者自己在文件开头就承认了）。你会继承一堆看不懂的结构，反而不如从干净模板开始。
更好的做法：
 用启动器「新建工程」生成一个干净项目，需要某个效果时，再回到这个教程里找到对应章节，把那一小段代码抄过去。
08
三个练习，每个 15 分钟
动手比读十遍有用
开始之前
先复制一份再动。
 别直接改 SDK 里的这个目录 —— 升级 Ren'Py 时它会被覆盖。
      把整个 
tutorial
 文件夹复制到桌面，然后改副本。
      另外记得先把 
project.json
 里的 
"type":"hidden"
 删掉，否则启动器里找不到它。
练习 1
改一句台词
约 5 分钟
用记事本或 VS Code 打开 
game/script.rpy
。
搜索 
My name is Eileen
，它会出现在 
label start
 里。
把引号里的英文改成你想说的话（中文也可以，记得存成 UTF-8）。
关掉游戏，重新启动。
会看到：
开场第一句话变了。
你学到：
台词就是 
角色 "内容"
，改文本不需要懂任何编程。
练习 2
加一个自己的章节
约 10 分钟
打开 
game/script.rpy
，找到 
Section(_("Quickstart"))
 下面那一串 
Tutorial(...)
。
在这一串的最后加一行：
Tutorial("my_chapter", _("我自己的章节"))
注意开头空 4 格，和上下几行
对齐
（Python 靠缩进认层级，错了会报错）。
在文件末尾、
label end:
 之前，加上：
label my_chapter:
    scene bg washington
    e "这是我加的章节！"
    return
这里的 
label
 要顶格写，里面的内容空 4 格；
e
 就是开头定义的那个角色 Eileen。
重新启动，点进目录最下面看看。
会看到：
菜单里多了一条，点进去就是你写的一句台词，演完自动回目录。
你学到：
这个教程的「注册 + 自动生成菜单」机制，也就能理解 
call
 和 
return
 的配合。
练习 3
换个背景，加一个立绘
约 15 分钟
打开 
game/script.rpy
 的 
label start
，把 
scene bg washington
 改成 
scene bg cave
（洞穴背景，工程里已经有）。
把下面的 
show eileen vhappy
 改成 
show lucy happy at right
（换个人物，站右边）。
在下一句台词后面加一行 
with dissolve
，看看淡入效果。
如果还想试：把 
play music "sunflower-slow-drag.ogg"
 换成 
play music "renpyallstars.ogg"
。
想让 Eileen 彻底离场：在下一句台词前加一行 
hide eileen
。
会看到：
开场变成了洞穴 + Lucy + 另一首曲子。
你学到：
图片的「名字 → 文件」对应关系，以及 
scene
（换场景）、
show
（放人物）、
at
（位置）、
with
（转场）四个最常用的指令。
    做完这三个，你就已经掌握了 Ren'Py 最核心的 8 个指令。接下来缺的只是「怎么把界面做漂亮」和「怎么组织一个长剧本」——
    前者看 
gui.rpy
 和进阶里的「屏幕基础」，后者去看 The Question。
09
之后往哪走
按这个顺序，不容易迷路
1
先玩一遍这个教程
（可以切中文）。不用看代码，就当一个玩家玩，知道 Ren'Py 能做到什么程度。
2
用启动器新建一个空工程
，跑起来看看。你会发现它和这个教程的骨架一模一样 —— 因为 
script.rpy
、
options.rpy
、
gui.rpy
、
screens.rpy
 就是标准模板。
3
读 The Question
（启动器里也有）。它是官方推荐的「短篇完整游戏」范例，结构正常，适合当你的第一个参照。
4
把这个教程当字典。
 想做某个效果时（比如「让文字一个字一个字出现」），回到教程里找到对应章节，把那一小段抄进自己的项目。
5
遇到具体问题时查官方文档
（renpy.org/doc/html）。文档和这个教程是配套的：教程里每个功能，文档里都有完整参数说明。
最后一句
      这个工程看起来吓人，是因为它把「10 种语言的翻译」和「一整套演示素材」都塞进来了。
剥掉这两样，它就是一个 9,512 行、25 个文件的普通 Ren'Py 项目
